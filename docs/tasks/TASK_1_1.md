# TASK 1.1 — نظام المحتوى (مسودة)

> **لا تُنفَّذ** قبل إغلاق TASK 0.3 وتقريرها. هذه البطاقة مسودة لتسريع المرحلة التالية.

**المرحلة:** 1 | **الفرع:** `task/1-1-content-loader` | **المنفّذ:** وكيل واحد فقط (يحدده المالك)

## الهدف
تحميل الوحدات والأصوات والخرائط من مجلد `content/` عبر مانيفستات JSON، مع تحقق صارم ورسائل خطأ واضحة، دون تغيير أي شكل في الواجهة.

## المطلوب
1. إنشاء `src/content/loader.ts` يقرأ:
   - `content/units/<id>/unit.json`
   - `content/sounds/manifest.json`
   - `content/maps/<id>/manifest.json`
2. إنشاء `src/content/schema.ts` يتحقق من كل مانيفست، ويعيد قائمة أخطاء بالمسار واسم الملف، ولا يرمي استثناء صامتاً.
3. إضافة مثال واحد لكل نوع في `content/`: وحدة واحدة، وحدث صوتي واحد، وخريطة واحدة.
4. المحرك لا يتغير سلوكه: إذا لم يوجد الحدث الصوتي في المانيفست، يستخدم `soundSynth` الحالي كبديل.
5. اختبارات في `src/content/loader.test.ts` تغطي: مانيفست صحيح، حقل ناقص، معرّف مكرر، ملف صوت غير موجود.

## الملفات المسموح بتعديلها
- `src/content/**` (جديد)
- `content/**` (جديد)
- `package.json` (إضافة سكربت الاختبار فقط)
- `docs/**`

## الممنوع
- تغيير الرسم أو الواجهة أو الفيزياء أو A*.
- حذف `soundSynth.ts` أو `packs/studioUnits.ts` في هذه المهمة.
- إضافة مكتبات جديدة دون ذكرها في التقرير.

## معايير القبول
- الفحوص الأربعة خضراء.
- المحمّل يقرأ المثال كاملاً ويعيد الأخطاء المتوقعة في الاختبارات.
- تقرير `docs/tasks/TASK_1_1_REPORT.md` يذكر الأوامر ونتائجها وما لم يُنجز.
