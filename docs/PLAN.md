# خطة مشروع الاستوديو

> نقطة الدخول: `docs/START_HERE.md`.

**المستودع:** `mimr5445-dev/rws-2` (كان `rws2-java`، والتغيير بيد المالك).
**الغاية:** استوديو احترافي ينتج فيديوهات تشرح الحروب وتاريخ الدول للنشر على السوشال ميديا.

## المبادئ
1. **الثبات:** كل مكوّن له حدود واضحة، والمحرك حتمي (نفس المدخل = نفس النتيجة).
2. **المحتوى ملفات:** الخرائط والوحدات والأصوات والشخصيات والسيناريوهات مجلدات ومانيفستات، لا أكواد مدمجة.
3. **المحرك لا يعرف الملفات:** يطلب الحدث باسمه (مثل `tank.fire`) والوحدة باسمها، والمانيفست يحدد الملف.
4. **كل خطوة قابلة للتحقق:** لا تُعتمد مهمة قبل نجاح الفحوص وكتابة تقرير.
5. **الاستمرارية:** أي نموذج يستلم العمل يبدأ من `docs/HANDOFF.md`.

## المصدر الوحيد للحقيقة
- **GitHub (`main`)** هو المصدر الوحيد. أي تغيير غير موجود فيه يُعتبر غير منجز.
- بيئة Google AI Studio بيئة تطوير مؤقتة: لا تُعتمد كمرجع، وأي عمل غير مدفوع إلى GitHub قد يضيع.

## الأدوار
- **المخطط (Claude):** يحلل الكود، يكتب بطاقات المهام، يراجع التقارير، يحدّث `ROADMAP.md` و`HANDOFF.md`.
- **Google AI Studio:** يطوّر داخل بيئته، ثم يدفع التغييرات إلى فرع في GitHub، ويفتح Pull Request ويدمجه بعد نجاح الفحوص. لا يعدّل على `main` مباشرة.
- **وكيل Arena:** يعمل مباشرة على GitHub في فرع منفصل، ويشغّل الفحوص، ويفتح Pull Request. لا يعدّل على `main` مباشرة.
- **المالك:** يحدد الأولويات ويعتمد البطاقة ويحدد المنفّذ لكل مهمة.

## قواعد العمل
- كل مهمة لها بطاقة في `docs/tasks/` وتقرير بعد الإغلاق بالقالب في `docs/templates/REPORT_TEMPLATE.md`.
- كل تغيير حالة يُسجَّل سطراً في `docs/PROGRESS.md`، وفي ملف المرحلة.
- **منفّذ واحد لكل مهمة.** البطاقة تحدد المنفّذ بالاسم، ولا يعمل منفذان على المهمة نفسها.
- **قبل البدء:** اسحب أحدث `main` إلى بيئتك، ثم أنشئ فرع `task/<id>-<slug>`.
- **أثناء العمل:** لا تعدّل إلا الملفات المسموح بها في البطاقة.
- **قبل الدمج:** إذا تغيّر `main` أثناء العمل، حدّث فرعك عليه وأعد تشغيل الفحوص. إذا ظهر تعارض في ملفات خارج نطاقك، توقف واكتب ذلك في `HANDOFF.md`.
- **فحوص إلزامية قبل الدمج:**
  - `bun install --frozen-lockfile`
  - `bun run lint`
  - `bun run test`
  - `bun run build`
- **تقرير إلزامي** في `docs/tasks/TASK_<id>_REPORT.md` يذكر الأوامر ونتائجها وما لم يُنجز.
- لا تغيير لتصميم الواجهة إلا في مهمة مخصصة لذلك.
- عند قرب نفاد الرموز: يُحدَّث `HANDOFF.md` ويُدفع إلى الفرع قبل التوقف.

## البنية المستهدفة
```
src/
  core/        المحرك المنطقي النقي (بلا رسم ولا صوت)
  content/     محمّل المحتوى والمانيفستات والتحقق منها
  renderer/    الرسم (PixiJS حالياً، ويُقيَّم Three.js لاحقاً للوحدات ثلاثية الأبعاد)
  audio/       مشغّل الأصوات بالأسماء (بدل المولّد الحالي)
  export/      التصدير: عارض بلا واجهة ينتج إطارات، ثم ffmpeg إلى MP4
  app/         غلاف التطبيق والحفظ كملفات مشروع
content/
  maps/<map_id>/         manifest.json + الخلفية + بيانات الحدود
  units/<unit_id>/       unit.json + النموذج أو الرسم + القدرات + أصوات الوحدة
  sounds/                manifest.json + ملفات الصوت (المفتاح = اسم الحدث)
  scenarios/             *.scenario.yaml
  characters/<id>/       الصور المرجعية والصوت
  tools/                 أدوات الرسم والتعليق
```

## مثال لعقد المحتوى
```json
// content/sounds/manifest.json
{ "tank.fire": { "files": ["vehicles/tank_fire_01.ogg", "vehicles/tank_fire_02.ogg"], "volume": 0.8 } }
```
```json
// content/units/tank_m1/unit.json
{ "id": "tank_m1", "model": "model.glb", "sounds": { "move": "vehicle.engine", "fire": "tank.fire" } }
```

## مرجع الوضع الحالي
- المشروع TypeScript وليس Java، ومبني على React 19 وVite 8 وPixiJS 8.
- المحرك يعمل بـ 60 خطوة في الثانية، وفيه A* ومدقق للسيناريوهات، وإصلاحات P0 منجزة وفق `TASK_0_2`.
- الوحدات SVG مكتوب داخل `src/packs/studioUnits.ts`.
- الأصوات مولّدة برمجياً في `src/renderer/soundSynth.ts`، ولا توجد ملفات صوت.
- الخرائط: خريطتان تجريبيتان، و`world-atlas` بدقة 110m.
- الدول: 14 ملف تجريبي.
- التصدير: `MediaRecorder` بصيغة WebM فقط.
- الحفظ: IndexedDB داخل المتصفح، وليس ملف مشروع.
- ملاحظات: لا يوجد كود Gemini ولا ملف خادم رغم وجود `express` و`@google/genai` و`server.js` في السكربتات. الوصف يذكر 30 خطوة/ثانية والكود 60. خمسة ملفات `Paste_*` غير مستخدمة. `App.tsx` 1697 سطراً و`studioRenderer.ts` 2540 سطراً.
