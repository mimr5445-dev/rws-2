# المعمارية والتقنيات (v1)

## 1. المبدأ

المنطق نقي وخالٍ من الواجهة. الواجهة والرسم والصوت والتصدير طبقات تقرأ المنطق وتنفذه، ولا تملكه.

## 4. قواعد الاعتماد (تُفرض بالأداة لا بالذوق)

- `core/**` لا يستورد من `react` أو `pixi.js` أو `src/ui` أو `src/render` أو DOM API.
- `render/`, `audio/`, `export/` تستورد من `core/` للقراءة فقط، ولا تستدعي أوامر تغيّر النموذج.
- `ui/` تستدعي الأوامر عبر `state/` فقط، ولا تعدّل المشروع مباشرة.
- `scripts/check-determinism` يفشل عند `Math.random` أو `Date` أو `performance.now` أو `setTimeout` داخل `core/**`.

## 5. تدفق البيانات

```
إجراء المستخدم → أمر (command) → النموذج الجديد → بصمة ← حفظ تلقائي
                                       ↓
                 المحاكاة(tick) ← الساعة ← المعاينة (Pixi + Web Audio)
                                       ↓
                 المصدِّر: نفس المحاكاة(tick) ← التقاط ← ترميز ← ملف
```

المعاينة والتصدير يستخدمان المحاكاة نفسها. الفرق الوحيد أن التصدير يخطو الـ ticks بنفسه ولا يعتمد على الزمن الحقيقي.

## 6. سجل القرارات (ADR) المبدئي

ADR-0001 اللغة وTypeScript. ADR-0002 Pixi.js بدلاً من DOM للمشهد. ADR-0003 الحتمية وtick. ADR-0004 IndexedDB للتخزين المحلي. ADR-0005 WebCodecs للتصدير مع مُغلِّف يُحدد بعد الفحص. ADR-0006 تأجيل 3D وWebGPU وتصدير 4K. تُكتب في `docs/adr/` بالصيغة: السياق، القرار، البدائل، النتائج.

## 7. ما لا نستخدمه في v1 ولماذا

- Remotion: يعتمد على متصفح بدون واجهة لكل إطار، وترخيصه يفرض رسوماً على الفرق الأكبر، وهو ليس محركاً لواجهة محرر تفاعلي.
- Unreal أو Unity: حجم وتعقيد لا يناسبان الأداة، وصعب ربطهما بمحرر ويب.
- Rust أو WebGPU للمحاكاة: مكاسب غير مثبتة قبل قياس، وتكلفة إعادة كتابة كاملة.
- Motion Canvas: مشروعه الأصلي غير نشط.
- مكتبات الذكاء الاصطناعي لتوليد الفيديو: خارج النطاق، والحتمية شرط أساسي.
