# ADR-0008: البصمة عبر Web Crypto فقط داخل النواة

- **الحالة:** معتمد
- **المرحلة:** 01

## السياق

`src/core` نقي ويُحزَّم للمتصفح، فلا يجوز أن يستورد `node:crypto`. البصمة مطلوبة بنفس القيمة في المتصفح وNode، وتُستخدم في الاختبارات وCI.

## القرار

- `core/hash` يستخدم `globalThis.crypto.subtle.digest('SHA-256')` فقط، ودالة غير متزامنة واحدة.
- التسلسل قبل التجزئة هو `canonicalize`: مفاتيح مرتبة، حذف `undefined`، تصفير `-0`، رفض `BigInt` والبنى الدائرية و`NaN/Infinity`.
- الاختبار يقارن ناتج Web Crypto بناتج `node:crypto` على التسلسل نفسه، ويُثبت التطابق.
- بصمة المشروع المرجعي مثبتة في الاختبار كقيمة صريحة؛ تغييرها يحتاج قراراً مكتوباً.

## البدائل

- **تنفيذ SHA-256 داخلي:** لا اعتماد على البيئة، لكنه كود حسّاس للتجزئة نكتبه بأنفسنا بلا داعٍ.
- **`node:crypto` مع حارس بيئة:** يكسر التعبئة للمتصفح ويخلق مسارين مختلفين.

## النتائج

- مسار واحد للبصمة في كل البيئات، ومقارنة مستقلة تُثبت التطابق.
- تكلفة: كل حساب بصمة غير متزامن (`await`)، وهو مقبول لأنه ليس في حلقة الرسم.
